1. PROJECT VISION & PHILOSOPHY
The Mantle Agentic Portal exists to make every person on earth able to access Mantle DeFi —
regardless of crypto experience. v5 achieves the deepest onboarding simplification yet: the portal never
asks a user to change their network. It does it for them, silently, the moment a wallet connects.
Intent over instruction: Natural language → agent routing, bridging, approvals, execution. Users
state goals, not steps.
Zero crypto prerequisite: Social login → embedded wallet auto-created. No MetaMask, no seed
phrases, no extensions required.
Network is infrastructure: Switching to Mantle happens silently in a background hook. It is never
surfaced as a user decision or warning.
Guided funding only when needed: If wallet is empty, portal shows funding options. If wallet is on
the wrong chain, it self-corrects without user involvement.
Chain-agnostic entry: Solana, EVM, Bitcoin wallets all supported via Privy. Non-EVM users are
guided to add an EVM wallet — that is the only chain-related prompt.
Gasless first experience: Paymaster covers first transactions. Empty-wallet users can still enter
and explore.

5. PRIVY INTEGRATION — FULL ARCHITECTURE
5.1 What Privy Is and Why It Was Chosen
Privy is an embedded wallet and authentication SDK — acquired by Stripe in June 2025. It lets any user
sign in with Google, Apple, Discord, email, or an existing wallet, and instantly receives a non-custodial
EVM (and/or Solana) wallet — no seed phrases, no browser extensions, no friction. 100M+ wallets
deployed across 1,500+ apps.
No seed phrases ever: 2-of-3 Shamir Secret Sharing. User never sees a private key.
Auto wallet on login: createOnLogin: 'users-without-wallets' provisions EVM + Solana wallets on
first sign-in. Completely invisible to the user.
15+ auth methods: Google, Apple, Twitter, Discord, email, SMS, passkey, MetaMask, Phantom,
WalletConnect, Coinbase, Farcaster, Telegram.
EVM + Solana in one SDK: Both chain types handled, with cross-chain account linking.
Built-in funding UI: useFundWallet() opens a native on-ramp modal. Supplemented by direct
on-ramp partner links.
Stripe acquisition: Payment-rail integration with Stripe Checkout expected — card-to-DeFi in the
most familiar checkout UI on earth.

6. ONBOARDING STATE MACHINE — 3 SCREENS,
NO NETWORK SCREEN
6.1 Design Principle: Network Switching Is Infrastructure, Not UX
This is the most important UX decision in the entire onboarding system. Network switching must never
be a user decision, a warning, a CTA, or a screen. It is an invisible technical operation that the portal
performs automatically the instant a wallet is connected.
The user's mental model is: 'I connected my wallet → I am on Mantle.' They should never know or
care what chain their wallet was previously on. The portal absorbs that complexity entirely.
Analogy: when you connect to a new Wi-Fi network, your phone doesn't ask you 'are you sure you want
to change networks?' and show a warning banner. It just connects. The Mantle portal treats network
switching the same way.

7. useAutoSwitchToMantle — THE CORE HOOK
7.1 How It Works
This hook is the single mechanism responsible for keeping every connected EVM wallet on Mantle at all
times. It runs as a side effect, not as a UI flow:
Trigger: Fires in a useEffect whenever the wallets array changes — specifically when any new
wallet address appears.
Per-wallet tracking: A useRef Set tracks which wallet addresses have already been switched. This
prevents duplicate switchChain calls on re-renders.
Silent chain read: Calls wallet.getChainId() first. If already on Mantle (5000), the wallet is logged as
switched and the hook exits. No unnecessary RPC calls.
Silent switch: Calls wallet.switchChain(5000) with no UI notification. Privy's embedded wallet
switches instantly. External wallets (MetaMask, Coinbase) show their own native confirmation — this
cannot be avoided for external wallets, but it is the wallet's own UI, not the portal's.
Fallback on failure: If switchChain fails (e.g. hardware wallet, some restricted external wallets), the
error is logged to console only. The user sees nothing. The portal still opens — they may need to
switch manually inside Interface 2 if they hit a tx that requires it.
Ambient status: The switching boolean returned by the hook drives a small inline 'Connecting to
Mantle…' spinner in the wallet check screen. It is not a warning, not a blocker, not a CTA.
7.2 Full Hook Implementation
function useAutoSwitchToMantle(wallets, onSwitched) { const switched = useRef(new Set()); //
addresses already handled const [switching, setSwitching] = useState(false); useEffect(() =>
{ const evmWallets = wallets.filter(w => w.chainType === 'ethereum'); if
(!evmWallets.length) return; const runSwitch = async () => { for (const wallet of
evmWallets) { if (switched.current.has(wallet.address)) continue; // already done try {
const currentChain = await wallet.getChainId?.().catch(() => null); if (currentChain ===
MANTLE_CHAIN_ID) { // Already on Mantle — mark and move on
switched.current.add(wallet.address); continue; } // Different chain — switch silently, no
UI setSwitching(true); await wallet.switchChain(MANTLE_CHAIN_ID);
switched.current.add(wallet.address); if (onSwitched) onSwitched(); } catch (err) { //
Silent fail — log only, never surface to user console.warn('[Mantle Portal] Auto-switch
failed for', wallet.address, '—', err.message); // Note: for external wallets (MetaMask
etc.), Privy's switchChain() // calls wallet_switchEthereumChain on the extension. If the
user // dismisses the MetaMask popup, this catch fires. We do not retry // or warn — the
user's action (dismiss) is respected silently. } finally { setSwitching(false); } } };
runSwitch(); // Dependency: re-run when wallet addresses change }, [wallets.map(w =>
w.address).join(',')]); return { switching }; }

8.3 What Was Removed — No Warning C
Previous versions included a 'Warning C' for wrong network, a 'Network Detection' screen (Screen 3),
and a manual 'Switch to Mantle' CTA button. All of these have been removed.
Why they were wrong:
Wrong network warning: Puts a technical infrastructure problem on the user's plate. They don't
know what 'Arbitrum' or 'chain ID 5000' means. They shouldn't need to.
Network Detection screen: An entire screen just to switch chains is extreme friction. It makes the
portal feel like every other DeFi app that constantly asks you to switch networks.
Manual 'Switch to Mantle' button: A CTA for something the portal can and should do automatically.
Asking the user to tap a button for a background operation is false friction.
The replacement: useAutoSwitchToMantle() — a silent background hook that handles the switch
before Screen 2 even finishes rendering in most cases.
The only reason a network warning could ever be justified is if switchChain() fails and the portal
genuinely cannot proceed without user help. Even then, the correct response is a contextual message at
the point of transaction failure, not a blocking warning banner at onboarding entry.

16. TROUBLESHOOTING & SUPPORT (v5)
16.1 Auto-Switch Issues
Issue: Auto-switch doesn't fire on MetaMask connect
MetaMask external wallets require the user to confirm the chain switch in their extension popup. The
hook calls switchChain() correctly, but MetaMask shows its own native popup. This is unavoidable for
external wallets — it is the browser extension's security model. For embedded Privy wallets, the switch is
fully silent and instant. Encourage users to use the embedded wallet (auto-created on social login) for
the smoothest experience.
Issue: Auto-switch fires but wallet still shows wrong chain
The wallet address may already be in the switched Set from a previous session. Clear the Set reference
by calling switched.current.clear() on logout, or key the Set on user ID rather than just wallet address.
Issue: switching stays true indefinitely
The setSwitching(false) call is in the finally block and should always fire. Check for an unhandled
promise rejection that bypasses the finally. Add a safety timeout: setTimeout(() => setSwitching(false),
5000) as a fallback.
Issue: getChainId() returns null for new embedded wallet
Privy's embedded wallet may not expose getChainId() immediately after creation. Add .catch(() => null)
as shown in the hook code and proceed to switchChain() directly — it is safe to call even if the current
chain is unknown.
16.2 Privy Issues
Issue: Privy silently breaks — wallets don't work
You are on http:// not HTTPS. Privy's Web Crypto API (key sharding) requires a secure context.
localhost is exempt. All other hosts must use HTTPS. This produces no error message.
Issue: Embedded wallet not created after login
Check createOnLogin: 'users-without-wallets' in PrivyProvider config and in the Privy dashboard under
your app's Embedded Wallets settings.
Issue: useWallets() returns []
Wait for ready === true from usePrivy() before relying on wallet data.
Issue: WalletConnect not working
Privy does not include WalletConnect by default. Install with the WalletConnect connector and provide
REACT_APP_WALLETCONNECT_PROJECT_ID.
